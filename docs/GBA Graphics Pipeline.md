### 1. GBA Graphics Pipeline: 4bpp, BGR555, and Metatiles

The Game Boy Advance uses tiled background modes (primarily **Mode 0** in Pokémon overworld and battle engines) powered by its 2D PPU hardware.

```
Raw Image (.png)
   │
   ▼ (gbagfx / porytiles)
8×8 Tiles (.4bpp) + Palette (.gbapal / BGR555)
   │
   ▼ (Grouped 2×2 or 4×2 into Metatiles)
Metatiles (.bin) + Metatile Attributes (.bin)
   │
   ▼ (PPU VRAM / BG Scanline Rendering)
16×16 Overworld Blocks rendered in Hardware Mode 0

```

#### Color Encoding: BGR555

GBA colors are 16-bit unsigned integers (`u16`) packed into 15 bits, leaving the most significant bit unused:

$$\text{Value} = (B \ll 10) \mid (G \ll 5) \mid R$$

* **Channels:** Red, Green, and Blue each take 5 bits ($0 \text{ to } 31$).
* **Conversion from 8-bit RGB:**

$$C_5 = \lfloor C_8 \times \frac{31}{255} \rfloor = \lfloor C_8 \gg 3 \rfloor$$


* **Byte Packing (Little-Endian):**
* Byte 0: `[G2 G1 G0 R4 R3 R2 R1 R0]`
* Byte 1: `[0  B4 B3 B2 B1 B0 G4 G3]`



#### Tile Representation: 4bpp Planar Tiles

* An $8 \times 8$ pixel tile consists of 64 pixels.
* In **4 bits-per-pixel (4bpp)** mode, each pixel references one of 16 palette indices ($0\text{--}15$). Index `0` is always transparent for sprites and non-backdrop background layers.
* 1 byte holds 2 pixels (1 nibble per pixel, little-endian: low nibble is the left pixel, high nibble is the right pixel):

$$\text{Byte Size} = \frac{8 \times 8 \times 4 \text{ bits}}{8} = 32 \text{ bytes per tile}$$



#### Metatile Hierarchies (Overworld Engine)

The hardware only understands $8 \times 8$ hardware tiles, but Pokémon game engines manage maps using $16 \times 16$ pixel blocks called **metatiles**:

| Layer Structure | Dimensions | Composition |
| --- | --- | --- |
| **Hardware Tile** | $8 \times 8$ px | 32 bytes raw 4bpp pixel data |
| **Metatile** | $16 \times 16$ px | $2 \times 2$ hardware tiles on bottom layer + $2 \times 2$ on top layer |
| **Map Grid Entry** | 2 bytes per cell | Metatile ID (bits 0–9) + Collision/Elevation (bits 10–15) |

* **`metatiles.bin`:** Stores the 8 hardware tile references forming a metatile (4 background tiles, 4 foreground tiles). Each entry includes the hardware tile index, palette bank ($0\text{--}15$), horizontal flip, and vertical flip flags.
* **`metatile_attributes.bin`:** Pairs collision bitmasks (`MB_IMPASSABLE`, `MB_SURFABLE`, `MB_DOOR`), ledge directions, and wild encounter behaviors with each metatile index.

### 2. Poryscript to Assembly Build Process

Poryscript abstracts low-level bytecode macros into a structured, C-style control-flow language. The conversion into executable code follows a multi-stage compilation flow:

```
Script File (.pory)
   │
   ▼ [poryscript CLI]
Assembly Script Include (.inc)
   │
   ▼ [arm-none-eabi-as] (via sym_common.ld / gnu make)
Object File (.o)
   │
   ▼ [arm-none-eabi-ld]
Final Linked ROM (.gba)

```

#### Step 1: Lexing, Parsing & Control Flow Lowering

The `poryscript` binary parses blocks like `script`, `text`, and `movement`. It eliminates high-level control structures (`if`, `elif`, `else`, `while`, `switch`) by emitting conditional branches targeting autogenerated assembly labels:

* **Source (`Route1.pory`):**
```pory
script Route1_Sign {
    lock
    if (flag(FLAG_SYS_POKEDEX_GET)) {
        msgbox("Welcome to Route 1!")
    } else {
        msgbox("...")
    }
    release
}

```


* **Lowered Output (`Route1.inc`):**
```assembly
Route1_Sign::
    lock
    checkflag FLAG_SYS_POKEDEX_GET
    goto_if_eq Route1_Sign_1
    msgbox Route1_Sign_Text_1, MSGBOX_DEFAULT
    goto Route1_Sign_2

Route1_Sign_1:
    msgbox Route1_Sign_Text_0, MSGBOX_DEFAULT

Route1_Sign_2:
    release
    end

```



#### Step 2: Text String Formatting & Preprocessing

* String literals are extracted into `poryscript`-generated labels (`Route1_Sign_Text_0:`).
* In the main assembly stage, the preprocessor `preproc` parses these strings using `charmap.txt`, mapping ASCII/UTF-8 characters directly to GBA character bytes (e.g., `'A'` $\to$ `0xBB`, `'\n'` $\to$ `0xFE`, terminator `'$'` $\to$ `0xFF`).

#### Step 3: Assembler and Linker Integration

1. The emitted `.inc` file is referenced inside the map's `scripts.inc` or unified scripts list.
2. The GNU assembler (`arm-none-eabi-as`) compiles this into a standard ELF object (`.o`) containing bytecode tables.
3. The linker assigns absolute ROM addresses ($0\text{x}08000000 + \text{offset}$), enabling the script engine's central interpreter loop in C (`RunScriptRet()`) to execute bytecodes via function pointer lookup tables.

### 3. m4a Sound Driver and mid2agb Workflow

The Pokémon decompilation projects run Nintendo's proprietary **m4a** sound engine (internally known as **Music Player 2000 / MP2K**, created by Yukio Kaneoka).

```
MIDI Authoring (.mid)
   │
   ▼ [mid2agb CLI]
Assembly Song File (.s)
   │
   ├── Notes, velocities, loops (.byte streams)
   └── Voicegroup Pointer Ref (--> sound/voicegroups/*.inc)
   │
   ▼ [arm-none-eabi-gcc / as]
Linked Song Entry in song_table.inc
   │
   ▼
m4a Sound Engine (DirectSound PCM + DMG Hardware Channels)

```

#### The Hardware Audio Mix

The GBA audio system combines two separate hardware subsystems:

1. **Game Boy Classic (DMG) Channels:** 4 legacy hardware synthesis channels (Channel 1: Pulse with sweep, Channel 2: Pulse, Channel 3: Custom wave, Channel 4: White noise).
2. **DirectSound A & B (PCM):** Two 8-bit digital-to-analog converter (DAC) channels driven by hardware timers and DMA transfers. The m4a software engine dynamically mixes multiple PCM software tracks into these two DMA buffers during V-Blank.

#### `mid2agb` Processing Pipeline

Composers author tracks in standard MIDI sequencers adhering to MP2K-specific channel limits and CC (Control Change) assignments:

1. **Track Separation:** MIDI sequence tracks are split into individual mono voice streams.
2. **Bytecode Conversion:** Events are mapped to m4a command bytes:
* **Note on / Duration:** Encoded as variable-length command bytes followed by pitch and velocity.
* **Tempo Changes (`TEMPO`):** Calculated based on the MIDI BPM relative to the GBA's $59.727\text{ Hz}$ frame timer.
* **Voice Changes (`VOICE`):** Translates MIDI program changes into indices inside a designated **Voicegroup** table.
* **Branching / Looping:** `mid2agb` translates MIDI markers (such as marker `[` and `]`) into assembly directives:
```assembly
.byte W00
.byte PNT, 0       @ Pointer loop setup
.word Song_LoopTarget

```





#### Voicegroups and Sample Playback

Each song points to a `Voicegroup` structure defining what sound plays when a note triggers on that channel:

```assembly
@ Example Voicegroup Entry in sound/voicegroups/
voicegroup000:
    .byte 0                @ Type: DirectSound PCM Sample
    .byte 60               @ Base MIDI key (Middle C)
    .byte 0                @ Pan / sweep settings
    .byte 0
    .word sound_sample_kick @ Pointer to raw signed 8-bit PCM data (.bin)
    .word 0x00000000       @ Loop start
    .word 0x00001240       @ Sample length

```

* **DirectSound Voices:** Specify sample rate, loop points, and pointers to signed 8-bit PCM waves.
* **DMG Voices:** Specify duty cycle, sweep envelopes, or fixed wave-pattern RAM addresses.
* **V-Blank Update:** Every frame, `m4aMain()` calculates ADSR envelopes, updates tone frequencies, mixes active PCM samples into the DirectSound ring buffer, and schedules the DMA transfer to the GBA's sound FIFO.
