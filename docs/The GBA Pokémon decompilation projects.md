The GBA Pokémon decompilation projects (`pokeemerald`, `pokefirered`, `pokeruby`, as well as `pokeemerald-expansion` / `pokeconfluence`) rely on a carefully tuned ecosystem of source code, graphics, audio, map, and binary formats. The toolchain (`gbagfx`, `porytiles`, `poryscript`, `mid2agb`, `arm-none-eabi-gcc`/`agbcc`, and GNU Make) processes these file types throughout the build pipeline.

Below is an exhaustive, detailed breakdown of all file types organized by their functional subsystems.

---

### 1. Source Code, Scripting & Data Definitions

- **`.c` / `.h` (C Source & Header)**:
  - The primary engine source code. Implements game logic, overworld handling, battle systems, RAM/EWRAM structures, and definitions located within `include/` and `src/`.
- **`.pory` (Poryscript Source)**:
  - High-level scripting files written in the Poryscript language. Contains map scripts, NPC dialogue, conditional branching, and event logic. Transpiled by the Poryscript compiler directly into GBA assembly `.inc` files at build time.
- **`.party` (`trainers.party`)**:
  - Used in `pokeemerald-expansion` as a declarative source text file for trainers. Parsed by the `trainerproc` tool into C structures (`trainers.h`) complete with IVs, EVs, personal traits, and dynamic teams.
- **`.json` (Metadata & Configuration)**:
  - Primarily utilized by **Porymap** and the build system:
    - `map.json`: Defines map ID, layout, weather, music, dimensions, and connected events.
    - `layouts.json`: Maps layout identifiers to primary/secondary tilesets and binary block paths.
    - `map_groups.json`: Configures the hierarchical order of map groups and regions.
    - `manifest.json`: Outlines tileset metadata, layers, and versioning.
- **`.csv` (Map & Attribute Tables)**:
  - `attributes.csv`: Used by Porytiles to define collision (`MB_NORMAL`, `MB_IMPASSABLE`, `MB_DOOR`, etc.), terrain types, and encounter flags for each $16 \times 16$ metatile.
  - Tabular data sheets for wild Pokémon encounters, items, and location mappings.
- **`.txt` (Control & Mapping)**:
  - `charmap.txt`: Translates UTF-8 text strings into the game's proprietary GBA character encoding during preprocessing via `preproc`.
  - `memory.txt` / `sym_*.txt`: Symbol tables and RAM layout maps (`sym_ewram.txt`, `sym_bss.txt`).

---

### 2. Assembly & Linker Files

- **`.s` / `.asm` (GNU Assembly)**:
  - Low-level ARM7TDMI assembly code. Implements critical interrupt service routines, BIOS calls (`libagbsyscall`), CRT0 runtime initialization, sound drivers (`sound/songs/*.s`), and hardware timers.
- **`.inc` (Assembly Include Macros)**:
  - Header and macro files for assembler sources. Encompasses map event definitions (`events.inc`), warp connections (`connections.inc`), map scripts transpiled from Poryscript (`scripts.inc`), and voice groups (`voicegroups/*.inc`).
- **`.ld` (Linker Script)**:
  - `ld_script.ld` and `ld_script_modern.ld`: Dictates physical memory allocation during the linking stage. Maps `.text` and `.rodata` to ROM (`0x08000000`), `.data` and `.bss` to EWRAM (`0x02000000`), and the system stack to IWRAM (`0x03000000`).

---

### 3. Graphics & Palettes (Source & Compiled Formats)

- **`.png` (Source Graphics)**:
  - The standard format for all raw artwork across the project. Ingested and processed by `gbagfx` or `porytiles`. Must adhere to 4bpp indexing (maximum of 15 colors + transparent Slot 0) and the 15-bit BGR555 color space.
- **`.pal` (JASC-PAL Palette)**:
  - 16- or 256-color ASCII palette files generated by graphic editing software or Porytiles. Structured with standard JASC headers (`JASC-PAL / 0100 / 16`) followed by RGB color triplets.
- **`.gbapal` (GBA Native Binary Palette)**:
  - Binary palette data generated by `gbagfx` from `.pal` or `.png` sources. Each color occupies precisely 2 bytes (16-bit), packed with 5 bits per channel (BGR555).
- **`.4bpp` / `.8bpp` (Raw Tile Data)**:
  - Raw planar pixel data segmented into hardware-native $8 \times 8$ tiles. In 4bpp mode, each pixel occupies 4 bits (1 nibble), resulting in exactly 32 bytes per $8 \times 8$ tile. In 8bpp mode (used for splash logos and intro cinematics), each pixel occupies 1 full byte.
- **`.1bpp` (Monochrome Tile Data)**:
  - 1 bit per pixel (8 bytes per $8 \times 8$ tile). Primarily used for Pokémon footprints (`footprint.png.1bpp`) and specialized monochrome font glyphs.
- **`.lz` (LZ77 Compressed Data)**:
  - Binary files compressed via the GBA BIOS LZ77 compression routine using `gbagfx` (e.g., `front.4bpp.lz` or `normal.gbapal.lz`) to minimize ROM footprints.
- **`.smol` / `.fastSmol` / `.smolTM`**:
  - Proprietary compression formats implemented in modern decompilation branches (e.g., Smol compression for tilemaps and battle backgrounds in `pokeemerald-expansion`), delivering significantly faster decompression speeds compared to standard GBA BIOS LZ77.

---

### 4. Maps, Tilesets & Metatiles (Binary Data Structures)

- **`.bin` (Generic Binary Blocks)**:
  - Heavily utilized for precompiled map and UI data structures:
    - `map.bin` / `blockdata.bin`: The core metatile grid of a map (storing tile IDs and elevation as 2-byte values).
    - `border.bin`: Border blocks surrounding maps in Porymap.
    - `metatiles.bin`: Encodes the composition of metatiles, mapping 4 or 8 individual $8 \times 8$ hardware tiles across background and foreground layers.
    - `metatile_attributes.bin`: Stores collision bytes, ledge jump directions, and terrain flags for each metatile (2 bytes in Emerald, 4 bytes in FRLG).
    - `tilemap.bin`: Predefined UI screen layouts (e.g., Pokédex, Pokénav, and start menus).

---

### 5. Audio & Music

- **`.mid` / `.midi` (MIDI Sequence Data)**:
  - Source composition and sound effect sequences authored in external MIDI sequencers. Encodes pitch, tempo, note velocities, and program control changes.
- **`.wav` / `.aif` / `.bin` (DirectSound PCM Samples)**:
  - Digital audio waveforms leveraged by the GBA m4a (Music Player 2000) DirectSound channels (e.g., percussion hits, custom instrument patches, and Pokémon cries located in `sound/direct_sound_samples/`).
- **`.s` (M4A Song Tracks)**:
  - Assembly tracks compiled from MIDI files using `mid2agb`. Contains voicegroup assignments, pattern event streams, and loop points linked directly into the game's master song table (`sound/song_table.inc`).

---

### 6. Build System, Emulation & Output

- **`.mk` / `Makefile` (GNU Make Build Configuration)**:
  - Build automation scripts (`Makefile`, `graphics_file_rules.mk`, `audio_rules.mk`, `spritesheet_rules.mk`). Governs prerequisite chains that convert `.png` to `.4bpp.lz`, `.mid` to `.s`, and manage dependency resolution.
- **`.o` / `.d` (Object & Dependency Files)**:
  - Intermediate artifacts emitted into the `build/` directory during compilation. `.o` contains compiled machine-code object modules; `.d` contains GCC-generated header dependency graphs for incremental compilation.
- **`.elf` (Executable and Linkable Format)**:
  - The complete, uncompressed executable produced by the linker, containing full DWARF debugging symbols. Used with debugging emulators such as **mGBA** for source-level C debugging.
- **`.gba` (Game Boy Advance ROM)**:
  - The finalized binary cartridge image (typically 16 MB or 32 MB mapped to `0x08000000`), ready for deployment to flash carts or emulators.
- **`.map` (Linker Memory Map)**:
  - Diagnostic text output from GNU `ld` documenting the exact ROM, IWRAM, and EWRAM addresses for every symbol, function, variable, and data table in the compiled binary.
- **`.sha1` (Checksum Verification)**:
  - Retains the SHA-1 digest of the retail baseline ROM to verify that code modifications yield a byte-matching 1:1 rebuild via `make compare`.
- **`.lua` (Emulator Scripting)**:
  - Integrated into **mGBA** to drive automated integration tests, cycle save states, inspect VRAM buffers, and orchestrate scripted battle simulations.
